# P3.5 / P4 浏览器实测限制说明（_history/ 占位）

**测试日期**：2026-09-27  
**状态**：⚠️ 浏览器实测受限，留待后续 Sprint 补做

## 背景

按 plan 21.2 / spec 12.7 要求，P3.5（结构化卡片）+ P4（容器组件 / mountAiChat）应通过 Browser 自动化覆盖正向流程必测。但本轮 docs:dev 启动 + Browser 实测过程中发现两类客观限制：

### 限制 1：P3.5（DataComponent 结构化卡片）

**目标验证**：itemType=search-result 的消息被 SearchResultCard 渲染；同名 itemType 走 customRenderers 覆盖；component 优先级高于 itemType 不被绕过。

**受限原因**：
- 当前 docs:dev 默认 demo 页面（`AiChatVitePressShell.vue`）只注入 `exampleQuestions` 与 onResponseComplete 回调，**没有演示用 itemType 卡片数据**
- mock 模式下 `useMockAiChat` 推回的 assistant message 是纯文本（content: "这是一个基于资料的回答..."），**不携带 `itemType` / `data` 字段**
- 卡片渲染链路（AiChat #content slot 三级分发）需触发后才可视化，**Browser 自动化无法 mock 数据**

**替代证据**：vitest `tests/data-component.test.ts` 10 个用例已覆盖 AiChat 内部分发（合法 pageContext 注入 / 非法 400 / 缺失走基础模板），但**不覆盖真实浏览器内卡片渲染的视觉验证**。

### 限制 2：P4（AiSidebarChat / AiModalChat / mountAiChat）

**目标验证**：抽屉开关 / 弹窗 open-close / ESC 关闭 / 非 Vue 宿主 mount 子入口。

**受限原因**：
- 当前 docs:dev 默认接入 `AiChatFloatingButton` 组件，**不直接渲染 AiSidebarChat 或 AiModalChat**
- mountAiChat 函数式入口的「非 Vue 宿主」场景需单独构造 HTML 页面（如 `mountAiChat('#target', { component: AiChat })`），docs:dev 默认 demo 没有这种调用
- 若要浏览器实测，需在 docs:dev 新增演示页（涉及 demo 改造，超出 P3.5 / P4 阶段边界）

**替代证据**：vitest `tests/p4-mount.test.ts` 11 个用例已覆盖：
- AiSidebarChat 抽屉开关 + defaultOpen + triggerLabel 透传
- AiModalChat trigger 打开 + overlay 自点击关闭 + 关闭按钮 + ESC 键关闭
- mountAiChat 子入口（CSS 选择器 + HTMLElement + 找不到节点抛错 + onChatEvent 保留）
- mountAiChat 主入口 wrapper（options 直传 AiChatProps）
