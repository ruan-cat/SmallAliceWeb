# 2026-11-10 从 Vercel 迁到 Cloudflare Workers 的设计

本文件由 Cursor 主代理使用 Grok 4.7 写成。源码盘点来自 [盘点部署配置](a295bda4-d0d4-4e5b-96b0-cff6434aa13b)、[排查 Workers 运行时阻断](f2472256-7501-473f-bb72-3713989892ba)、[盘点部署文档](409d649f-1deb-4843-91a6-141d6b77c736)。外部限额来自 2026-10 的 Cloudflare 文档，核对记录在同目录 `2026-11-10-external-evidence.md`。

这是待审设计。批准之前不改部署代码、不连 Git、不改 DNS、不删 Vercel 项目。

## 1. 客户会看到什么

小爱丽丝文档站和它的 AI 接口不再占用 Vercel Hobby 的部署存储。推 `dev` 做预览、推 `main` 做生产，构建分钟改记在 Cloudflare Workers Builds 上。文档站地址仍是 `https://drill.ruan-cat.com`，接口仍是 `https://smallalice-docs-ai-nitro-api.ruan-cat.com`，聊天和检索仍读现有 Neon 库 `neon-smallalice-ai-rag`。知识库同步的调度继续留在现有 GitHub Actions workflow `.github/workflows/rag-sync-schedule.yaml`。这次迁移不改这个文件，也不把扫描放进 Worker。

做不到的结果：免费套餐扛住这次迁移。Workers Free 的 HTTP CPU 是 10 毫秒，全账号同时只能构建 1 个项目。两个应用绑在同一个仓库上，Free 不够。

## 2. 目标

1. 文档站用 Workers Static Assets 发布 `docs/.vitepress/dist`。静态资源请求不计 Workers 请求费。
2. Nitro API 用官方预设 `cloudflare_module` 跑在 Worker 上，保留 `/v1/chat`、`/v1/search`、`/v1/models`、`/v1/knowledge/sync-runs` 和 evaluation 读接口。
3. 查询数据库继续用现有 Neon，不新建 project，不把库迁到 D1。
4. `main` 仍是生产分支，`dev` 仍是预览。一次推送可以构建两个 Worker，因此账号需要 Workers Paid 的 6 个并发构建。
5. 切流前两个 `workers.dev` 地址先按生产 URL 形状验收。DNS 只改 Cloudflare zone 里已经存在的两条 CNAME。

## 3. 非目标

1. 不把 `docs/docx` 扫描、embedding 批处理和 advisory lock 放进 Worker。
2. 不修改 `.github/workflows/rag-sync-schedule.yaml`，也不把 `docs/docx` 扫描搬进 Worker。该文件第 1–11 行记录了当前空转：`docs/docx` 被 gitignore，CI checkout 里没有知识源。这是现状，不是这次要修的行为。
3. 不把文档站上的 Neon 连接串复制到静态 Worker。
4. 不在本设计里更换聊天模型、embedding 模型或向量维度。
5. 不处理 `vercel project ls` 里其他仓库的项目。

## 4. 现行事实

两个 Vercel 项目都连着 `ruan-cat/SmallAliceWeb`，生产分支都是 `main`，Root Directory 都是仓库根，Node 22.x。文档站构建是 `pnpm run build`，产物 `docs/.vitepress/dist`。API 构建是 `pnpm --filter @ruan-cat-drill-doc/ai-rag-api run build:vercel`，内部为 `nitro build --preset vercel` 再把 `.vercel/output` 搬到仓库根。仓库里没有 `vercel.json`，也没有 `wrangler` 配置。

`ruan-cat.com` 的 NS 已经是 `vick.ns.cloudflare.com` 和 `dolly.ns.cloudflare.com`。`drill.ruan-cat.com` 的 CNAME 是 `cname.vercel-dns.com`。API 域名的 CNAME 是 `ad1c0a65577b8811.vercel-dns-017.com`。

API 运行时数据库驱动是 `postgres`（postgres.js）`^3.4.7`。`@neondatabase/serverless` 没有被运行时代码 import。查询和同步各用一条连接串。同步连接必须是 non-pooled，因为 `knowledge-sync.ts` 使用 `pg_try_advisory_lock`。

`createRagRuntime` 在初始化时用 `process.cwd()` 解析 `docs/docx`。真正读盘发生在同步服务里。`docs/docx` 被 gitignore，GitHub Actions 的 checkout 和 Worker 文件系统都没有这棵目录。`runSync` 在扫描结果为不完整时仍会拿 advisory lock，并向 `knowledge_sync_runs` 插入记录。因此 API 迁到 Worker 之后，HTTP 的 `/v1/knowledge/sync` 必须在调用 `sync` 之前拒绝，避免线上接口变成第二个写入者。GitHub Actions 走的是 `rag:sync` CLI，不经过这两个 HTTP 路由。

聊天路径已经是 Web `Response` 加 AI SDK `streamText`，没有 `@vercel/functions`。取消上游请求依赖 `nitro.config.ts` 里 Vercel 专有的 `vercel.functions.supportsCancellation: true`。换平台后这条配置没有等价物，必须用 workerd 上的真实断开重新证明。

文档站生产链接同时有两种形状。本地产物 `docs/.vitepress/dist/index.html` 里既有 `/about/`，也有 `/docx/.../*.html`。Workers 默认的 `auto-trailing-slash` 会把 `.html` 307 到无后缀路径，已发布的文章 URL 会变。

文档构建不是纯 VitePress。`turbo.json` 让 `docs:build:run` 依赖 `build:doc-in-vercel`。这条管线使用 `fs`、`child_process`、`sharp` 和 `@napi-rs/canvas`。它们只允许出现在构建机，不允许出现在 Worker 请求里。

本地 dist 有 7354 个文件、约 400 MB，没有单文件超过 25 MiB。这低于 Free 的 20000 文件上限，也低于单文件 25 MiB 上限。生产构建可能更多，切流前要再数一次。

## 5. 两个 Worker

|           Worker 名            |                                                配置文件                                                |                                  构建                                  |                运行时                 |
| :----------------------------: | :----------------------------------------------------------------------------------------------------: | :--------------------------------------------------------------------: | :-----------------------------------: |
|     `small-alice-web-odse`     |                                      仓库根 `wrangler.docs.jsonc`                                      | 仓库根 `pnpm run build`，然后 `wrangler deploy -c wrangler.docs.jsonc` |  静态资产加一层不改写 `.html` 的回退  |
| `smallalice-docs-ai-nitro-api` | Nitro `cloudflare_module` 生成的配置，仓库用 `nitro.config.ts` 的 `cloudflare.wrangler` 覆盖名字和绑定 |                 仓库根执行 API 包的 `build:cloudflare`                 | Worker。查询走 Hyperdrive。不同步扫盘 |

两个 Worker 的 Workers Builds Root Directory 都保持仓库根。不能把 API 的 Root Directory 改成 `packages/ai-rag-api`，否则 pnpm workspace 和 `ai-rag-core` 的构建会断。默认文件名 `wrangler.jsonc` 不能同时代表两个 Worker。部署命令必须带 `-c`。接通 Git 之前要用一次失败的空构建确认控制台的 “name 必须匹配配置” 读的是 `-c` 指定的文件。

文档站回退逻辑：资产存在就原样返回；路径以 `/` 结尾且未命中时，再取同路径下的 `index.html`；除此之外保持 404。不把 `.html` 重定向掉。浏览器导航会带 `Sec-Fetch-Mode: navigate`。只设 `html_handling: "none"` 时，这种请求在未命中文件后直接走 `not_found_handling`，`/about/` 会变成 404。因此文档站配置 `run_worker_first: true`，由 Worker 先做目录补齐。

## 6. 隐藏问题

1. **构建超时。** Workers Builds 的硬超时是 20 分钟，Paid 也一样。文档构建含 DOCX 转换和 VitePress。切流前必须有一次完整构建的分钟数。超过 18 分钟就改为 GitHub Actions 构建、Wrangler 只负责上传，不在超时边缘赌。
2. **并发构建。** Free 同时只能构建 1 个。同一次 `main` 推送会打文档站和 API。Paid 才有 6 个并发。
3. **版本不会随构建日志删除。** 构建日志保留 90 天，版本本身不跟着删。这不是 Vercel Deployment Storage 的同名配额。切流后要看静态资产版本是否按份计存储。文档产物约 400 MB，不能假设旧版本免费无限留。
4. **环境变量 5 KB、构建期最多 64 个。** 连接串放得下。PEM 和大 JSON 放不下。秘密用 `wrangler secret`，不写进配置文件。构建变量不会自动变成运行时变量。`process.env` 在 Worker 全局作用域是空的，只能在请求里读。
5. **git-changelog。** `shouldDisableGitChangelog()` 只在 `provider === "vercel"` 且没有 `.git` 时禁用。Cloudflare 构建不是 Vercel。有 `.git` 时插件会跑。浅克隆会导致 changelog 变短；没有 `.git` 时会在 `git config --local` 失败。构建机必须带 `.git`。历史不够时扩展禁用条件，不删插件。
6. **Corepack。** 两个 Vercel 项目都有 `ENABLE_EXPERIMENTAL_COREPACK=1`。Workers Builds 要显式启用 Corepack，否则会重演 pnpm 元数据拉取失败。
7. **postgres.js 与 Hyperdrive。** 请求路径按 Workers 的外部 Postgres 规则走 Hyperdrive，连接的仍是现有 Neon。同步 CLI 继续拿 non-pooled 直连，禁止把 Hyperdrive 的池化串配进 `NITRO_SYNC_DATABASE_URL`。若 Hyperdrive 下 `postgres()` 在 workerd 里连不上，查询路径再改 `@neondatabase/serverless`，同步 CLI 不动。
8. **同时只许 6 条连接等响应头。** 检索加 embedding 加聊天模型如果并行 `fetch`，第 7 条会排队。先保持现有串行，不在迁移里加并发。
9. **128 MB 内存。** 不要在 Worker 里缓冲整段聊天或整库向量。现有流式响应保持。`zod` 仍是 3.x，不借这次升级。
10. **取消生成。** `supportsCancellation` 不能翻译成 Workers 配置。用 workerd 断开客户端后，断言上游 `abort` 发生。证明不了就在交付里写明生产停止按钮仍可能让上游继续，不把它说成已经对齐。
11. **预览环境变量缺口。** `NITRO_DATABASE_URL`、`NITRO_KNOWLEDGE_SYNC_TOKEN`、`NITRO_CRON_SECRET` 在 Vercel 上没有 preview target。迁到 Workers 时生产与预览分开配，不沿用这个缺口。
12. **Development Sensitive。** 这是 Vercel CLI 的限制。Cloudflare secret 没有这个分叉，不必为了“三环境 Sensitive”再做一套。
13. **文档站误带数据库变量。** `small-alice-web-odse` 上有整套 `POSTGRES_*`。静态 Worker 只需要构建期的 `VITE_RAG_API_BASE`。
14. **本地单槽。** `.vercel/project.json` 当前绑的是 Nitro 项目，和 `vercel-deploy-tool.config.ts` 里的文档站不是同一个项目。迁移期间不要 `vercel link` 来回切。
15. **账号里还有别的 Vercel 项目。** 本次只动上面两个名字。

## 7. 已经替你定下的决定

1. 用 Workers，不用 Pages。Nitro 文档把 `cloudflare_module` 定为推荐预设，Pages 预设只留给需要 Pages 特性的应用。
2. 文档站用 `html_handling: "none"` 加目录 `index.html` 回退，避免 307 改写 `.html`。
3. API 请求路径的普通查询和写入使用 `@neondatabase/serverless`。同步 CLI、`reserve()` 和 drizzle 迁移保持 `postgres.js`。Vercel 生产路径上的驱动这次不改，等 API 的 10 毫秒实测再接入。
4. 用户已决定：知识库同步调度继续留在 GitHub Actions。Worker 只承载文档站和 Nitro API 的线上请求。HTTP `/v1/knowledge/sync` 在 `knowledgeSourceRoot` 有值但目录不存在时返回 501，且不调用 `sync`。`rag-sync-schedule.yaml` 和 `scripts/rag-sync.ts` 保持原样。
5. `build:vercel` 保留到 `workers.dev` 验收通过。新脚本叫 `build:cloudflare`，两套构建并存。
6. 切流当天只改两条 CNAME。回滚就是改回现在的 `vercel-dns` 目标。Vercel 项目至少再留一个发布周期。
7. `AGENTS.md`、`README.md`、`openspec/specs/ai-rag/deployment/spec.md` 的正文在切流验收之后再改。现在只在 `AGENTS.md` 加了一句“设计未生效”。

## 8. 已经由你定下的边界

1. 知识库同步调度继续留在 GitHub Actions。`.github/workflows/rag-sync-schedule.yaml` 本次不改。
2. 不购买 Workers Paid。构建按顺序排队。文档站优先走 Workers Builds；构建机跑不通克隆或转写时，改由 GitHub Actions 构建再把产物交给 Worker。
3. 两个 Worker 按依赖链做路径过滤。`packages/ai-rag-core` 同时影响文档站和 API。
4. `drill-docx` 是公开仓库，构建机不配 GitHub token。
5. 先迁文档站。API 只有一次真实 `/v1/search` 的 CPU 低于 10 毫秒才切到 Worker，否则继续留在 Vercel。
6. Worker 要具备对现有 Neon 的查询和普通写入能力，供以后把 API key 存进数据库。这个新功能本身不在本次迁移里实现。
7. 请求路径换成 `@neondatabase/serverless`。`rag:sync`、`run-parameter-evaluation.ts` 和 drizzle 迁移继续用 `postgres.js`。Worker 放 pooled `NITRO_DATABASE_URL` 和查询密钥，不放 non-pooled `NITRO_SYNC_DATABASE_URL`。

## 9. 切流顺序

1. 先做文档站的 `workers.dev`，用本地 dist 对照 `/about/` 和一篇 `.html`。
2. 再做 API 的 `workers.dev`，对照 `/v1/search`、一段流式 `/v1/chat`，以及源目录缺失时同步接口 501。
3. 两次构建分钟数都低于 18 之后，才把 Git 接到 Workers Builds。生产分支 `main`，预览分支包含 `dev`。
4. 最后改两条 CNAME。改之前先把 Vercel 生产的 URL 行为记下来，改完用同一组 URL 复验。
5. 复验通过之后，再改 `AGENTS.md`、`README.md` 和 OpenSpec deployment 规格。那时候再开一个 OpenSpec change，不在本次设计里直接改现行规格。

## 10. 成功时你能核对的证据

1. `drill.ruan-cat.com` 的 NS 路径不变，CNAME 不再指向 `vercel-dns`。
2. 一篇现有 `.html` 文章返回 200，地址栏后缀还在。
3. `/about/` 返回 200。
4. `/v1/chat` 能流出回答，断开后有 abort 证据，或者交付文字明确写了没有。
5. 对 Worker 发 `/v1/knowledge/sync` 得到 501，Neon 的 `knowledge_sync_runs` 不新增空跑。
6. `.github/workflows/rag-sync-schedule.yaml` 的 diff 为空。
7. Vercel 这两个项目不再因为 `main` 推送产生新的 Production deployment。
