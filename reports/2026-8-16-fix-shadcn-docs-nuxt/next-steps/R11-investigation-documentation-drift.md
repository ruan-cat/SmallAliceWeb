# R11 调查文档与 PR 描述存在阶段性漂移

- **优先级**：P2
- **状态**：OPEN
- **类型**：知识治理 / AI agent 误导风险

## 风险说明

本轮调查持续时间长、实验多，仓库中已经出现多个“当时正确、现在过时”的状态描述。例如：

- `README.md` 仍把 E3 写成执行中；
- `TEST-PLAN.md` 仍把 E5-A/E5-B 写成运行中；
- `final/FINAL-FIX.md` 仍写“尚未达到最终修复验收标准”，内容停留在 E2 阶段；
- 主 PR #11 body 仍以 E2 为下一阶段，并包含已经失效的工具状态描述。

这些文件不是恶意错误，而是长任务中自然产生的时间切片。但对新的 AI agent 来说，如果没有识别“历史记录 vs 当前状态”，很容易重复已经完成的实验、恢复已否定配置、甚至误判最终候选。

## 建议加固任务

1. 指定一个**当前状态唯一入口**，建议是本报告根 `README.md` 或 `final/FINAL-FIX.md`。
2. 把 E0–E7 的最终状态一次性回填：PR、SHA、run/job、结论、是否进入最终候选。
3. 对历史实验文件保留原始证据，不重写历史；仅增加 `最终状态` / `superseded by` 标记。
4. 更新主 PR #11 body，使其与最终候选、风险登记表和经验 skill 一致。
5. 对 `TEST-PLAN.md` 标记哪些步骤已完成，哪些已转移到 `next-steps/`。
6. 增加“最后同步日期 + canonical candidate SHA”，让下一 agent 能快速判断文档是否过期。

## 验收标准

- [ ] 新会话只读根 README + FINAL-FIX 即可得到当前真实结论。
- [ ] E0–E7 不存在互相冲突的“运行中/已完成”状态。
- [ ] 主 PR body 不再把已完成实验写成下一步。
- [ ] 工具可用性等瞬时状态不再被长期写成当前事实，或明确标注时间。
- [ ] `next-steps/README.md` 被当前状态文档引用。

## 不要做什么

- 不要删除历史实验中真实失败证据。
- 不要为了“整洁”把当时的实验设计改写成事后诸葛亮版本。
- 不要让多个文件同时声称自己是唯一最新状态但内容不同。
