# 2026-08-25 AI RAG 生产流式协议误判与 goal 自动续跑事故

## 1. 问题现象

`ai-rag-phase2` 的生产浏览器流式回归未完成。执行过程中将 `/v1/chat/completions` 的失败错误归因为模型不支持 SSE，并在 goal 自动续跑中重复尝试同一类阻塞路径，未及时暂停。用户报告这轮无效重复已造成约 100 美元消耗。

## 2. 实际根因

生产模型的协议前提判断错误：该模型应通过 `POST https://api.code-tab.com/v1/responses` 调用，使用 `model: "gpt-5.6-luna"`、`input`、`stream: true`，并消费 Responses API SSE 事件。`/v1/chat/completions` 失败只能说明该请求路径或协议不匹配，不能推出模型不支持流式响应。

执行控制同样失效：goal 自动续跑把“继续尝试”当作默认推进策略，但没有把“同一阻塞”定义为可比较的指纹，也没有在工具缺失、外部权限缺失或连续三次同类失败后转换为暂停和升级。因此每轮都没有产生新的诊断信息，却仍继续消耗调用资源。

## 3. 关键误导点

- Chat Completions 端点的失败被错误地当作模型能力结论，而非协议兼容性信号。
- `/v1/models` 被当作流式可用性的间接前置检查；它不能替代一次真实的 Responses SSE 请求。
- HTTP 成功、来源帧或本地受控流被错误地视作接近生产流式闭环的证据；它们都不能证明生产浏览器能够接收、停止并收敛真实上游流。
- 自动续跑缺少失败计数、阻塞指纹和外部依赖门禁，导致重复执行没有新增信息的尝试。

## 4. 有效纠正

本次先修正 OpenSpec `2.1.4` 的任务合同：明确端点、请求体、Responses SSE 事件处理、Nitro 的 Responses provider 或 `fetch` 到 AI SDK data stream 的适配选择，以及生产浏览器证据。

同时在任务中写入硬暂停规则：工具缺失、外部权限缺失，或同一阻塞连续三次出现时，停止自动续跑，在 `agent-progress.md` 记录阻塞指纹、次数和所需外部条件。此处是流程纠正；生产流式实现和浏览器验收仍未完成，不能将本记录视为 `2.1.4` 已修复的证据。

## 5. 验证方式

任务工件验证：`openspec/changes/ai-rag-phase2/tasks.md` 的 `2.1.4` 必须同时包含 `/v1/responses`、`gpt-5.6-luna`、`input`、`stream: true`、Responses SSE、AI SDK data stream 和连续三次阻塞暂停规则。

后续实现验证：生产浏览器 Network 应显示脱敏后的 `/v1/responses` 流式请求；页面需显示首段文本、可操作停止入口、停止后的 abort 与保留内容，并能跳转到真实来源锚点。只有这些 fresh 证据齐全，才能勾选 `2.1.4`。

## 6. 后续约束

- 为外部模型先确认端点和事件协议，再解释失败原因；禁止从单个不兼容端点推出模型能力结论。
- 每次重试必须改变一个可验证前提并写明预期新增证据；没有新增前提或证据时不得重试。
- 自动任务必须保存阻塞指纹和尝试次数；连续三次相同指纹，或发现工具、权限、账户配置缺失时，立即暂停并向用户报告所需条件。
- 不以本地 mock、HTTP 200、资源加载计数或历史缓存代替生产浏览器流式验收。
